# Travel Web / PWA 可行性验证结果

核验日期：2026-10-12。当前阶段为独立验证与迁移准备，原生 App、平台配置和手机业务数据保留。

## 当前判断

现有业务规则、Timeline / Sheet、品牌图钉可以复用到网页；高德国内地图与搜索、Google 海外地图与搜索都能工作。IndexedDB 适配器可以在原 Commands 之外提供原子提交、冲突重试、回滚与恢复。PWA 已验证缓存启动和编辑，并具备明确的更新入口。

用户已在真实 iPhone Safari 确认搜索新增、仅到达时间／备注／键盘保存、添加到主屏幕后创建行程并断网重开继续编辑均正常；补充反馈也确认 Google 成田国际机场搜索与图钉、Sheet 标题下／列表空白处拖动、日期箭头切换以及箭头排序后的重开保留正常。当前可行性验证已完成，具备正式迁移的技术依据。

## 已加入的验证机制

- 版本化网页资源缓存；必须完整安装后才报告就绪。地图、搜索、Key 配置和旧备份响应不进入缓存。
- 更新需要明确操作，编辑草稿保护不依赖用户记得导出。Worker 不删除 IndexedDB；旧缓存与其它页面分别保护。
- 文件导出、选择与恢复；新备份有 SHA-256 校验，旧格式可读。浏览器持久保存状态单独显示，未获准时明确提示保留独立备份。
- 根据 VisualViewport 调整编辑器可见高度；桌面 390×500 实测无横向溢出，保存按钮在可见范围。该布局证据与 iPhone 键盘反馈分别记录。

网页资源缓存与数据存储必须分开管理。缓存网页不会自动保护浏览器中的业务数据；持久保存也不能代替独立文件备份。[Expo PWA 指南](https://docs.expo.dev/guides/progressive-web-apps/)、[WebKit 存储政策](https://webkit.org/blog/14403/updates-to-storage-policy/)

## 临时入口与交付

经用户明确批准，临时 HTTPS 入口受访问码保护，两小时后同时关闭源服务和隧道。原行程备份接口在该入口被禁用，只提供公共样例验证；安全密钥保留在本机代理。原始数据库、备份和 Key 均未进入可下载验证包。

此入口依赖本机进程，域名每次变化，适合验证；长期使用需要稳定地址。[Cloudflare 临时隧道说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

交付目录：`prototypes/web-feasibility`。可运行包：`dist-validation.zip`，按包内 README 使用 Node.js 启动，不需要 Expo 构建依赖。

## 正式迁移边界

当前页面仍是两趟公共样例的技术验证。首页足迹、完整 Trip 管理／日期／Unscheduled／编辑字段与原生全量 UI 尚未移植；账号和云备份也未实现。

正式使用应沿用已验证的两种来源与业务规则，建立稳定 HTTPS 地址，再迁移最新备份到正式浏览器存储并再次核对全部字段。现有整库快照适配器还需要容量、性能与升级验证。短时间离线重开不能证明数月后的数据留存，独立备份应继续保留。

后续建议 **Sol xhigh**：地图来源、持久化与数据切换存在实际数据完整性风险。
