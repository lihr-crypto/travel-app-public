# 时间输入框与选中背景留白（2026-10-30）

用户实机反馈到达时间输入框异常变高，日期与每日行程的选中背景贴近文字，并有相邻分割线露在圆角外。用户明确要求修改后直接合并部署。

## 原因与修正

- 旧 `.time-row>div{flex:1}` 在列布局中填满父行；出发时间有“清除”按钮时，另一列空输入随网格被拉高。实际 App 复现出发 44.8px、到达 96.8px。时间字段改为顶端对齐，输入容器不参与剩余高度分配，日期/时间控件固定 44px；不修改保存与清除语义。
- 日期与日期策略的背景向两侧扩展到 16px 内边距，负 margin 等量抵消，文字原坐标保持。选中日期和前一行的分割线透明，增加 4px 行间隙，避免圆角边缘露线。
- Web 每日行程暴露 `aria-selected` 状态，用伪元素把背景向左右各延展 16px，文字、实际行宽/高和拖动测量均保持；选中行及其前一行的边线透明，仍保留原 1px 边框宽度。原生样式与行为不变。
- Web 运行时不把 `accessibilityState.selected` 转成 DOM 标记，实际浏览器发现后改用直接 `aria-selected`，覆盖状态切换测试并重新完成全量检查。

## 验证

- 两项 CSS 回归在旧实现下失败，修复后通过；Web 行选择标记切换有组件回归。
- `npm run check` 正常退出：145 suites / 1025 passed / 1 skipped；6 项原型与临时 SQLite 云验收通过，Web/PWA 构建通过。
- 实际 App、独立 SQLite 样例与 320/393px Chromium 验证：仅出发/仅到达时间时控件均高 44px、同排顶端一致、窄屏无横向溢出。
- 393px 日期日序号 x=24、日期 x=100；320px 对应 x=20/96。选中背景与文字间距 16px；中间选中行与前一行边框透明，15 天列表中单双位序号日期列保持对齐。
- 每日普通/选中行实际宽度 345px、高度 80px、文字区域 x=24；选中背景扩展至 x=8，边框透明。选中前后的尺寸不变，未修改手势实现。
