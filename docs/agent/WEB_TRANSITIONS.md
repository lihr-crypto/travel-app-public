# Web 页面与窗口过渡（2026-10-31）

用户要求页面与窗口之间切换得更顺滑。本轮实现 Web 过渡层，不修改原生 App、数据命令、保存/删除确认、云协作或地图服务。

## 动作与范围

- 弹窗使用短距离滑入和淡入，进入 240ms、退出 160ms；菜单进入编辑、旅行管理子页和地点选择等替换使用短交叉淡化。
- 首页/总览/每日/未安排的面板标题和内容使用约 220ms 的轻过渡，日期切换沿用既有路由和滚动重置逻辑。
- 覆盖新建、行程操作、编辑/地点选择、管理旅行/日期、共享、设置和内部确认；首页地图地点预览同样接入。
- 仅面板与内容有过渡名称，根页面不作快照，地图/WebGL 不设过渡名称。没有给真实 Bottom Sheet、时间行或拖动元素增加 transform，没有复制可交互 DOM 或额外挂载一份页面。
- 地图选点阶段的窗口直接更新，含 `.picker-map` 的弹窗和遮罩也排除捕获，避免地图作为弹窗子元素进入快照。
- 文本输入、时间字段、选中状态、地图更新、拖动位置和数据命令仍使用原来的直接更新。动画不等待退出结束后才保存，不为点击添加固定延时。

## 实现与兼容

`web/src/motion.js` 将同一事件中的窗口关闭/打开合为一次状态提交，通过浏览器 View Transitions 的更新回调提交 React DOM。等待捕获期间的新意图合入同一批；已有动画可被新操作打断，旧完成回调不清理新动画。原生回调被跳过、拒绝或启动异常时，状态更新仍只执行一次。

- 优先使用支持浏览器的同文档 View Transitions。依据 [WebKit 的 Safari 18 说明](https://webkit.org/blog/15443/news-from-wwdc24-webkit-in-safari-18-beta/)，它在旧/新状态间进行捕获和过渡；代码检测实际 API，而非推测用户系统版本。
- React 的同步提交只用于捕获回调这类浏览器集成，按 [React flushSync 文档](https://react.dev/reference/react-dom/flushSync) 使用；普通输入不经过同步过渡队列。
- 开启 `prefers-reduced-motion` 时，新增过渡关闭。隐藏页面立即提交，不等待暂停的捕获；浏览器已提供返回动作时跳过额外应用动画。
- 不支持该 API 时保持即时更新，旧浏览器可用轻量弹窗入场 CSS 回退，退出保持即时操作；不提供不可靠的 DOM 克隆动画。CSS 回退使用静态能力判断，避免每次过渡标记清除后重复播放入场。

## 验证

- 新增 11 项状态/DOM 测试，覆盖同事件合并、捕获期间快速操作、旧动画中断、回调不重放、API 不支持、减少动态效果、隐藏页、地图选点排除、原生导航跳过、异常回退以及菜单→编辑→Escape。
- 实际 React DOM 测试确认窗口切换后只保留一个活动对话框，关闭恢复焦点和滚动锁，输入不触发新过渡且内容即时更新。

## 浏览器恢复后

在 320/393px 及桌面宽度检查：主页→总览→每日/未安排、上/下日、菜单→编辑、编辑→地点→返回、日期选择、共享/设置和内层确认。重点观察面板高度不同、长列表已滚动、快速连点、动画中途返回、减少动态效果以及键盘打开/关闭时是否闪跳；确认地图无新增黑帧，关闭后无透明遮罩和失去焦点。保持所有数据写入在独立样例环境，生产入口只读查看并取消表单。
